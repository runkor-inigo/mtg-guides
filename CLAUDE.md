# Speaker Elves Guide

Legacy MTG guide for "Speaker Elves" (BG Elves). Current list: 9 Oct 2026 (runkor, MTGO): the 5 Oct list with Elvish Visionary back in the main deck for Marwyn, the Preserver, and Alpha Deathclaw in the sideboard for Primaris Eliminator. See README.md for the file structure and ROADMAP.md for pending decisions. LEGACY.md holds the Legacy heuristics the guide follows, with their source, status and when they do not apply (internal, not published); read it before writing strategy text, and keep it in step with the Heuristics pane.

## Decisions

- Static site: plain HTML, CSS and JS (`index.html`, `css/`, `js/`, `assets/`). No Node, no Vite, no npm, no build step.
- Deployed by Vercel from the `main` branch on GitHub (runkor-inigo/mtg-guides). A push to `main` redeploys. Public URL: https://speaker-elves.vercel.app/ (the `*-runkors-projects.vercel.app` deployment URLs sit behind Vercel login).
- All user-facing text is in English. Dark style, green palette; the highlight is mint warming to gold at its right edge.
- GSAP is self-hosted at `js/vendor/gsap.min.js` (no CDN) and loads before `js/menu.js` and the numbered scripts.
- Respect `prefers-reduced-motion`, but the sidebar "Animations" switch can override it (`motion-on` / `motion-off` classes on `<html>`).
- Design skills live in `.claude/skills/` (local only, gitignored): emil-design-eng, impeccable, design-taste-frontend and redesign-existing-projects, installed 8 Oct 2026 from their GitHub repos, plus frontend-design and the GSAP skills. Impeccable's hooks are not enabled (they would download and run its binary after every edit). Use them for design passes; the project rules here still win (no build step, dark green palette).
- Never scrape pages behind bot protection (e.g. MTGGoldfish deck pages behind Cloudflare). Use public listings and mtgo.com.

## When a new list arrives

runkor sends the new 75 (an MTGO screenshot or export). Follow these steps, in this order, and tell runkor what changed before touching any plan by hand:

1. **Diff it** against the Current 75 rows in `#deck` (main and sideboard, card by card) and confirm the totals: 60 main, 15 sideboard. Name the cards that leave and arrive.
2. **Card data:** every arriving card needs Oracle text checked on Scryfall, an entry in `COMBO_CARD_ART` (js/02.js, rules in "Card art") and, if it is a sideboard card, its cost in `SB_COSTS` and `CARD_COSTS` (js/01.js; `CARD_COSTS` copies `SB_COSTS` early, so set both) and a short name in js/13.js.
3. **Current 75:** update the rows (name and tag), the "Current list · <date>" note, the toolbar date in js/07.js and the package table in Deck Construction. Check js/12.js (mulligan odds sets) if a land, dork or Green Sun's Zenith target changes.
4. **Maybeboard:** a card that leaves moves to the "ours" shelf (job, the plans it served, why it left, with the date); a card that arrives leaves the Maybeboard. Make its thumbnail in `assets/thumbs/` (208×290, WebP q80). The total stays as it is unless a new card enters the archive.
5. **Plans:** add a documented conversion block just before `upgradeMatrix()` in js/01.js (one rule per swap, applied to every plan), never edit plans one by one silently. Check every plan still balances (ins = outs) and has no card outside the 75.
6. **Text:** search index.html for every mention of the cards that left and arrived (Heuristics, Interaction Windows, Game Plans pivots, Speaker Loop, Sequencing, Sources, Construction flex boxes) and rewrite what is no longer true; the guide must never tell the reader to find a card that is not in the 75.
7. **Review the plans with the heuristics** (LEGACY.md) and show runkor a comparison: the mechanically converted plan against a plan built from the heuristics, with the reasons. Apply only what runkor approves.
8. **Check and record:** local check at 1440 and 390 px (no console errors, no 404), footer "Last updated" date, CLAUDE.md, ROADMAP.md and README.md.

## Card art

Applies to card images (`COMBO_CARD_ART` in js/02.js) and matchup art (`ART` in js/09.js, `assets/matchups/<key>.webp`).

- Always the first printing: the earliest paper printing on Scryfall, excluding promo, token, memorabilia and digital-only sets. Find it with `https://api.scryfall.com/cards/search?q=oracleid:<id> game:paper&unique=prints&order=released&dir=asc`.
- Never borderless, showcase, extended-art or full-art versions. If the first printing is one of these, take the earliest printing that is not.
- When a first printing has several arts (Alpha basics), use the lowest collector number.
- Source: Scryfall only, through its public API (`User-Agent` and `Accept` headers, ~100 ms between requests). Cards use the `normal` image (488×680); matchup art uses `art_crop`.
- Card art used as a header or banner (cards, heroes, thumbnails; runkor, 9 Oct 2026): use the illustration only, Scryfall's `art_crop` of the same printing, never a crop of the full card (old frames show their border). Frame each image by its focal point with `background-position` (e.g. Natural Order: the leopard's eyes, top left, so anchor it at the top), and check it at desktop and phone sizes.
